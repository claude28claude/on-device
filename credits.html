Credits and licences

Everything this site uses is stored inside the site itself and served from the same address as the page. Nothing is fetched from anyone else's servers, which is both a privacy decision and the reason it works offline.

Bundled libraries

Everything through Phase 2 was written for this project. Phase 3 changed that: working with PDFs needs two libraries that would be unreasonable to write from scratch, so they are used, stored inside this site, and served from the same address as the page.

How to check they have not been tampered with

Borrowed code is shipped compressed, which makes it unreadable — so instead of asking you to read it, here is something better. Every borrowed file has a fingerprint recorded in assets/vendor/VENDOR.json. Download the same version from the public npm registry, compute its SHA-256, and compare. If they match, the file here is byte-for-byte the published release.

Why borrowed code changes nothing about the promise

These libraries cannot contact anything, whatever they might contain. The security policy at the top of every page permits requests to this site and refuses every other address, and the browser enforces that before any of this code runs. If one of them ever tried, the attempt would be blocked and counted in red on the How this works page. That protection does not depend on trusting the library, which is the point.

Also included, from pdf.js

Rendering a PDF faithfully sometimes needs more than the code: typefaces for documents that did not embed their own, character maps for Chinese, Japanese and Korean text, and two small WebAssembly decoders for JPEG 2000 images and colour profiles. All are part of the same Apache 2.0 package and all are stored here. Their own licences (Foxit, Liberation, OpenJPEG, QCMS) are in assets/vendor/pdfjs/.

Altogether the borrowed files come to about 4.5 MB. They are deliberately not part of the first visit — somebody who only wants to resize a photograph never downloads them. They arrive the first time a PDF tool is opened, with a progress bar, and are kept from then on.

Still written here

Everything else, including all six image tools, the reader that pulls hidden information out of a photograph, and the code that removes it without re-compressing the picture. Those two were written from the format specifications rather than borrowed, because doing the job properly means editing the file’s own bytes rather than redrawing the image.

ffmpeg (WebAssembly) Trimming video and audio Around 30 MB, and the video tools are not built. Listed here so its absence is a decision rather than an oversight.
One licence still to settle

The best-known HEIC decoder for browsers is built on a library released under the LGPL, which is not one of the permissive licences this project promised to stick to. Rather than quietly include it, Phase 2 shipped without any bundled decoder at all: On Device asks your browser to open HEIC photos, and says plainly when it will not. Safari usually can; Chrome, Edge and Firefox usually cannot. Bundling one is a licence decision still to be made.

Fonts

None are downloaded. The site uses whichever typeface your own device already provides for its interface, which is why the first page load is so small and why there is no request to a font service.

Icons

All drawn for this project as plain shapes inside the page. There is no icon font and no icon service.

The app icons and social image

Generated by a small script in this repository that writes the image files directly, pixel by pixel, using nothing but what Node.js already includes. No image library, no design tool, no download.
