How this works, and how to check

Every site that handles your files says it respects your privacy. Saying it costs nothing. This page is here so you do not have to take our word for it.

What “it runs in your browser” actually means

When you use most file websites, your file is copied over the internet to a computer owned by that company. Their computer does the work and sends a result back. Your file sat on someone else’s hard drive, at least for a while. What happened to it after that is a matter of trust.

This site does not do that. Your browser — Chrome, Safari, Firefox, Edge — is already a very capable piece of software. It can read a PDF, decode a photo, and re-encode an image without help from anyone. This site is a set of instructions that tells your browser how to do those jobs. The instructions travel to you; your file never travels anywhere.

There is no account to make, because there is nothing to attach an account to. There is no upload progress bar, because there is no upload. There is no “your file will be deleted in one hour” promise, because your file was never anywhere that needed deleting.

Check it yourself, with your browser’s own tools

You do not need to know anything technical for this. You are going to open a panel that shows every request your browser makes, then use a tool and watch nothing happen.

  1. Press F12 on Windows, or Cmd + Option + I on a Mac. A panel opens.
  2. Click the tab named Network.
  3. Click the small circle or “Clear” button to empty the list.
  4. Now go and use any tool on this site. Drop in a file. Do the thing.
  5. Look back at the Network tab. It stays empty. Nothing was sent.

On a phone this is harder to do, which is why the next check exists.

The check that settles it: turn your internet off

Visit this site once, so your browser has the files. Then switch off wifi and mobile data completely — aeroplane mode is fine. Now come back and use it.

Everything still works. Every tool, on every file.

This is worth sitting with for a second, because it is not a claim, it is a proof. A site that uploaded your files could not possibly work with the internet switched off. If it works offline, the work is happening on your machine. There is no third possibility.

The rule the browser enforces on us

Every page of this site carries a Content Security Policy — a short set of instructions to your browser about what the page is permitted to do. Ours says, in effect: this page may only load and contact files from its own address, and nothing else, ever.

The important part is who enforces it. Not us. Your browser reads that policy before it runs a single line of our code, and refuses anything that breaks it. If we made a mistake, or if some piece of code we included tried to phone home, the browser would block it and you would see it counted in red above.

Being straight with you about one detail: the strictest possible setting would forbid the page from making any request at all, including for our own files. We cannot use that, because several tools are large programs that are only fetched from this site when you actually open them — a PDF password module, an offline text recogniser. So the policy permits requests to this site’s own address and refuses every other address in the world. The practical result is the same: there is no destination your file could be sent to, and the browser will not permit one to be invented.

There is also no analytics, no error reporting, no fonts or icons loaded from anyone else’s servers, and no cookies. Not as a policy choice we might revisit — the policy above makes them technically impossible without you noticing.

Read the code

Everything written for this site is plain HTML, CSS and JavaScript, deliberately not compressed or scrambled, so that what runs is what you can read. Nothing is hidden behind a build step.

Two exceptions, stated plainly: the PDF tools use two open-source libraries, pdf-lib and pdf.js, which are shipped compressed because that is how they are published. Instead of asking you to read them, every borrowed file has a published fingerprint you can check against the official release — see the Credits page. And it matters less than it sounds: borrowed code is bound by the same policy as ours, so it cannot reach anything either.

The file worth reading first is assets/js/netguard.js. It is about two hundred lines, it is commented in plain English, and it is the thing that counts and blocks requests. If you know someone who reads code, that is the file to show them.

The public source-code link will be added here as soon as the site is published. Until then, it is on the machine it was built on.
